# 2026-09-21

## Qué se construyó

- Backend FastAPI con los seis módulos enrutados bajo `/api/v1`: CV, vacantes,
  captura, postulaciones, inteligencia y entrevistas.
- Modelo de datos completo en `app/models/entities.py` (12 tablas), con `JSONB`
  para lo que produce el LLM y `Vector` para el matching.
- Capa de servicios con la lógica de negocio separada de HTTP.
- `docker-compose.yml` con Postgres 16 + pgvector y Redis, en puertos 5433/6380.
- Frontend inicializado con `create-next-app` (Next 16, React 19, Tailwind 4) y
  cimientos propios: cliente de API tipado (`src/lib/api.ts`, `types.ts`), kit de
  componentes, gráficos y navegación. Las pantallas por módulo siguen pendientes.
- Vault de Obsidian dentro del repo (`docs/`) con arquitectura, modelo de datos,
  mapa de API, guía de desarrollo y siete ADR retroactivos.

## Decisiones tomadas

Se documentaron en retrospectiva las decisiones ya tomadas en el código:

- [ADR 0001](../adr/0001-postgres-pgvector.md) — Postgres + pgvector como única BD
- [ADR 0002](../adr/0002-embeddings.md) — embeddings locales por defecto
- [ADR 0003](../adr/0003-sin-migraciones.md) — `create_all` en vez de Alembic
- [ADR 0004](../adr/0004-extension-en-vez-de-scraping.md) — extensión, no scraping
- [ADR 0005](../adr/0005-tailoring-con-aprobacion.md) — el tailoring propone, no guarda
- [ADR 0006](../adr/0006-salida-estructurada-llm.md) — cliente LLM único y estructurado
- [ADR 0007](../adr/0007-single-tenant.md) — un solo usuario, sin auth

Sobre la documentación: el vault vive **dentro** del repo y usa enlaces markdown
relativos en vez de `[[wikilinks]]`, para que las mismas notas se lean igual en
Obsidian y en GitHub. Un vault aparte se habría desincronizado del código.

## Problemas encontrados

- `LLM_FAST_MODEL` usa el alias corto `claude-haiku-4-5`; el id completo es
  `claude-haiku-4-5-20251001`. Pendiente de fijar.
- `backend/tests/` está creado pero vacío.
- `backend/smoke_tmp.py` es un script de prueba manual con un CV de ejemplo;
  debería moverse a `backend/tests/` o borrarse.

## Segunda mitad de la sesión

Se cerró el proyecto de punta a punta:

- **Frontend completo**: `/cv`, `/vacantes` con detalle, `/pipeline`,
  `/entrevistas`, `/ajustes` y el panel. Más `components/diff.tsx` para el diff
  de tailoring.
- **Extensión de navegador** en `extension/` (Manifest V3), con extractor propio
  por portal y autofill. Cierra el módulo 3, que estaba solo como contrato.
- **Primeros tests**: 55 pasando en `test_taxonomy.py` y `test_scoring.py`, con
  marcador `needs_db` para que la suite corra sin Postgres.

Dos correcciones de fondo que valía la pena registrar:

- `extract_skills` contaba solapamientos: una mención de «React Native» sumaba
  también a «React». Ahora se marcan las posiciones ya atribuidas y cada tramo
  cuenta una vez. Además las siglas de una o dos letras (`js`, `go`, `r`) solo
  se detectan en la forma en que se escriben en un CV, para no capturar prosa
  como «go to the store».
- En `applications.py` las tareas se creaban con `application_id` a pelo y
  `db.add()`. La colección `application.tasks` ya cargada no se enteraba, así
  que la respuesta salía sin tareas. Ahora se añaden por la relación.
